# Настройка синхронизации

Синхронизация работает **по коду, без регистрации и без почты**. Данные шифруются в браузере,
на сервер уезжает только зашифрованный блок. Персональные данные не собираются вообще —
поэтому требования 152-ФЗ к хранению данных россиян в России здесь не возникают.

Настройка занимает около пяти минут и ничего не стоит.

## Как это устроено

Из твоего кода из 16 знаков выводятся **две независимые** вещи:

| Что | Как получается | Где используется |
|---|---|---|
| Идентификатор строки (64 знака) | PBKDF2 → HKDF, ветка `bucket-id` | Ищем свою строку в базе |
| Ключ AES-256 | PBKDF2 → HKDF, ветка `payload-key` | Шифруем данные в браузере |

Сервер видит только непонятный идентификатор и шифртекст. Он **не знает ни кода, ни содержимого**,
поэтому даже утечка базы ничего не даёт. И наоборот: по идентификатору нельзя вычислить ключ.

PBKDF2 с 210 000 итераций делает перебор кода дорогим, а сам код из 68 возможных знаков
даёт около 97 бит энтропии — перебрать его нельзя.

Обмен идёт не в таблицу напрямую, а через две функции. Прямого доступа к таблице у публичного
ключа нет, поэтому **выгрузить список чужих строк невозможно** — можно получить только ту строку,
чей длинный идентификатор ты уже знаешь.

## Шаг 1. Создать проект Supabase

1. Зайди на [supabase.com](https://supabase.com), зарегистрируйся (бесплатно, карта не нужна).
2. **New project.** Имя любое, регион — ближайший, например Frankfurt.
3. Пароль базы данных придумай и сохрани — в приложении он не понадобится, но пригодится тебе.
4. Подожди пару минут, пока проект создастся.

## Шаг 2. Создать таблицу и функции

Открой в панели **SQL Editor** → **New query**, вставь всё это целиком и нажми **Run**:

```sql
-- Таблица: только непонятный идентификатор и зашифрованный блок.
-- Ни имён, ни почты, ни чего-либо читаемого здесь нет.
create table if not exists public.sync_buckets (
  bucket_id  text primary key,
  payload    text not null,
  updated_at timestamptz not null default now()
);

-- Полностью закрываем прямой доступ к таблице.
-- RLS включён, а политик нет — значит через обычный REST её не прочитать.
alter table public.sync_buckets enable row level security;
revoke all on table public.sync_buckets from anon, authenticated;

-- Чтение: только по точному идентификатору. Список строк получить нельзя.
create or replace function public.sync_pull(p_bucket_id text)
returns table (payload text, updated_at timestamptz)
language sql
security definer
set search_path = public
as $$
  select b.payload, b.updated_at
  from public.sync_buckets b
  where b.bucket_id = p_bucket_id;
$$;

-- Запись: создать свою строку или обновить её.
create or replace function public.sync_push(p_bucket_id text, p_payload text)
returns timestamptz
language plpgsql
security definer
set search_path = public
as $$
declare
  v_now timestamptz := now();
begin
  -- Идентификатор всегда ровно 64 шестнадцатеричных знака — мусор не пройдёт
  if p_bucket_id !~ '^[0-9a-f]{64}$' then
    raise exception 'Неверный идентификатор';
  end if;

  -- Ограничение размера одного блока. Два мегабайта — примерно вдвое больше,
  -- чем набирает очень активный пользователь за три года.
  if length(p_payload) > 2000000 then
    raise exception 'Слишком большой блок данных';
  end if;

  -- Потолок на число строк. Ключ anon публичный по замыслу: он лежит
  -- в коде страницы, и записать что-нибудь в базу может кто угодно, а не
  -- только владелец приложения. Прочитать чужое при этом нельзя, но без
  -- потолка посторонний мог бы создать сколько угодно «карманов»
  -- и забить бесплатные 500 МБ, после чего синхронизация встала бы у всех.
  --
  -- Проверяем только при создании новой строки: иначе по достижении
  -- потолка перестали бы сохраняться и уже существующие данные.
  -- Одна строка — один человек, так что сотни хватает с большим запасом.
  if not exists (select 1 from public.sync_buckets where bucket_id = p_bucket_id)
     and (select count(*) from public.sync_buckets) >= 100 then
    raise exception 'Хранилище заполнено';
  end if;

  insert into public.sync_buckets (bucket_id, payload, updated_at)
  values (p_bucket_id, p_payload, v_now)
  on conflict (bucket_id) do update
    set payload = excluded.payload,
        updated_at = v_now;

  return v_now;
end;
$$;

grant execute on function public.sync_pull(text) to anon;
grant execute on function public.sync_push(text, text) to anon;
```

Должно появиться «Success. No rows returned».

> **Если база уже настроена раньше.** Просто выполни этот же блок ещё раз — он написан так,
> что повторный запуск безопасен: таблица создаётся только при отсутствии, функции
> перезаписываются, данные не трогаются. Так подхватится потолок на число строк,
> которого в первой версии не было.

## Шаг 3. Прописать адрес и ключ

В панели: **Project Settings** → **API**. Понадобятся два значения:

- **Project URL** — вида `https://xxxxxxxx.supabase.co`
- **anon public** ключ — длинная строка, начинается с `eyJ`

Создай в папке проекта файл `.env.local`:

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

Файл `.env.local` в git не попадает. Ключ `anon` **не секретный** — он и рассчитан на то, чтобы
лежать в браузере. Настоящий секрет здесь только твой код синхронизации, и он никуда не уходит.

Перезапусти `npm run dev` — переменные окружения читаются при старте.

## Шаг 4. Включить на устройствах

1. На первом устройстве: **Ещё** → **Синхронизация** → **Создать код**. Нажми на глаз, чтобы
   увидеть код, и на кнопку копирования.
2. Перенеси код на второе устройство любым способом.
3. На втором: **Ещё** → **Синхронизация** → **Ввести существующий** → вставь код → **Подключить**.

Дальше всё само: приложение синхронизируется при открытии и через пару секунд после правок.

## Что важно знать

**Код невозможно восстановить.** Он нигде не хранится, кроме твоих устройств — в этом и смысл.
Потеряешь код — потеряешь доступ к серверной копии. Локальные данные при этом останутся.
Сохрани код в менеджере паролей.

**Кто знает код — видит твои кешбэки.** Не отправляй его в открытых чатах.

**Код лежит в хранилище браузера, а оно общее для всего домена.** Сайт опубликован по адресу
`ivabatru.github.io/cashbackrubanks/`, и для браузера домен здесь — `ivabatru.github.io`,
один на все проекты аккаунта, выложенные через GitHub Pages. Путь после домена роли не играет.
Пока это единственный такой сайт, прочитать код неоткуда. Но если с того же аккаунта появится
второй сайт, его страницы получат доступ к коду синхронизации и ко всем кешбэкам — достаточно
будет подключить туда сторонний скрипт вроде счётчика посещений. Полностью это решается только
своим доменом. Пока домена нет, правило простое: **с аккаунта `IvabatRu` не публиковать
через Pages ничего постороннего.**

**Данные объединяются, а не перезаписываются.** Если правил на двух устройствах без интернета,
при синхронизации сохранится всё; при правке одной и той же записи победит более поздняя.
Удаления тоже переносятся правильно — удалённое не возвращается.

**Удаления «помнятся» полгода.** Если устройство не выходило на связь дольше, его старая копия
может вернуть то, что ты удалял. Тогда просто удали ещё раз.

**Синхронизация работает только по https или на localhost.** Браузер запрещает шифрование
на незащищённых адресах, поэтому по локальной сети `http://192.168.x.x` раздел будет выключен.

**Бесплатный проект Supabase засыпает** после недели без запросов — его нужно будет разбудить
кнопкой в панели. Если пользуешься приложением регулярно, этого не случится.

**Бесплатного тарифа хватает с большим запасом.** Все данные одного человека — это несколько
килобайт, а в бесплатном плане 500 МБ. Десять человек не займут и промилле.
