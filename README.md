# Кешбэк — мои банки

Справочник своих банковских кешбэков. Заполняешь один раз в месяц: банк → категория → процент.
Потом на главном экране нажимаешь «Аптеки» и сразу видишь, в каком банке какой процент и где выгоднее.

Работает на Windows и Android из одного кода: это PWA — веб-приложение, которое
устанавливается как обычное, со своей иконкой, и работает без интернета.

## Что внутри

- **196 банков** — полный реестр участников СБП (данные НСПК), с логотипами. Логотипы лежат
  локально в `public/logos/`, поэтому список работает офлайн.
- **Популярные банки сверху.** Альфа-Банк, ВБ Банк (Wildberries), ВТБ, Газпромбанк, МТС Банк,
  Озон Банк, ПСБ, Райффайзен, Сбербанк, Совкомбанк, Т-Банк, Яндекс Банк — отдельным блоком
  в алфавитном порядке, ниже полный список и поиск по нему.
- **40 встроенных категорий** плюс возможность добавить свои, с выбором значка.
- **Месяцы.** Следующий месяц открывается для заполнения **с 27 числа** текущего — банки как раз
  объявляют новые категории в конце месяца. Прошлые месяцы остаются в архиве только для просмотра.
- **Кнопка «Скопировать из прошлого месяца»** — если категории не изменились, не нужно вбивать заново.
- **Синхронизация между устройствами по коду** — без регистрации и без почты, данные шифруются
  в браузере. Настройка: [SYNC-SETUP.md](SYNC-SETUP.md).
- Тёмная и светлая тема (по умолчанию — как в системе).
- Резервная копия в файл и восстановление из него.

## Запуск

Нужен Node.js 18 или новее (проверено на 24).

```bash
npm install
npm run dev
```

Откроется на `http://localhost:4173`.

Порт у `dev` и `preview` специально одинаковый: `localStorage` привязан к адресу **вместе с
портом**, и на разных портах браузер считает приложение разными сайтами — данные выглядели бы
пропавшими.

У этого решения есть побочный эффект, который уже обработан в коде. У собранной версии
(`npm run preview`) есть service worker, кеширующий всю сборку. После переключения на `dev`
он остаётся в браузере и продолжает отдавать старую сборку — кажется, что правки не применяются.
Поэтому `src/main.tsx` в режиме разработки сам удаляет такой worker и один раз перезагружает
страницу.

Если правки всё же не видны, нажми **Ctrl+Shift+R**. Не используй в DevTools «Clear site data» —
она удалит вместе с кешем и твои кешбэки; достаточно кнопки **Unregister** в разделе
Application → Service workers.

## Установка как приложение

### Windows

1. `npm run build` — соберёт папку `dist/`.
2. `npm run preview` — поднимет сервер на `http://localhost:4173`.
3. Открой этот адрес в Chrome или Edge → в адресной строке появится иконка установки
   (или меню `⋮` → «Установить приложение»).

Приложение появится в меню «Пуск» со своей иконкой и будет открываться в отдельном окне,
без адресной строки.

### Android

Важное ограничение: **браузер разрешает устанавливать PWA только по HTTPS** (исключение —
`localhost`). Открыть по локальной сети `http://192.168.x.x:4173` можно, приложение даже
заработает, но кнопки «Установить» не появится, офлайн-режим не включится и синхронизация будет
недоступна — шифрование в браузере тоже требует защищённого адреса.

Поэтому для телефона проект нужно выложить на бесплатный хостинг статики. Самый быстрый путь,
без git и без командной строки:

1. `npm run build` — соберёт папку `dist/` (около 2,9 МБ, 206 файлов).
2. Открой [app.netlify.com/drop](https://app.netlify.com/drop) и перетащи туда папку `dist`.
3. Через несколько секунд получишь адрес вида `https://что-то-случайное.netlify.app`.
   Чтобы сайт не удалился, заведи бесплатный аккаунт и нажми «Claim site» — там же можно
   переименовать адрес на что-то читаемое.
4. На телефоне открой этот адрес в Chrome → меню `⋮` → «Установить приложение».

Годятся и Vercel, и Cloudflare Pages, и GitHub Pages.

### GitHub Pages

Дольше в настройке, но потом всё делается само: отправил правку — сайт пересобрался и обновился.
Заготовка уже лежит в [.github/workflows/deploy.yml](.github/workflows/deploy.yml).

Нужен git — если его нет:

```powershell
winget install Git.Git
```

Дальше один раз:

1. Создай на GitHub пустой репозиторий, например `cashback`.
2. Отправь туда код:

   ```bash
   git init
   git add .
   git commit -m "Приложение для учёта кешбэков"
   git branch -M main
   git remote add origin https://github.com/ИМЯ/cashback.git
   git push -u origin main
   ```

3. В репозитории: **Settings** → **Pages** → Source: **GitHub Actions**.
4. Там же: **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
   Добавь два секрета с теми же значениями, что в `.env.local`:
   `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
5. Вкладка **Actions** — сборка запустится сама. Через пару минут сайт будет по адресу
   `https://ИМЯ.github.io/cashback/`.

Базовый путь `/cashback/` подставляется в сборке автоматически из названия репозитория,
руками ничего считать не нужно. Исключение — если назовёшь репозиторий `ИМЯ.github.io`:
тогда сайт окажется в корне домена, и в workflow нужно заменить `VITE_BASE` на `/`.

Файл `.env.local` в репозиторий не попадает — он в `.gitignore`, поэтому настройки и вынесены
в секреты.

### Про ключ Supabase в опубликованном приложении

В любом варианте выкладки ключ `anon` оказывается внутри собранного JavaScript, то есть
доступен всем, кто откроет сайт. Так и задумано: этот ключ не секретный. Твои данные защищает
не он, а код синхронизации, которого на сервере нет.

Именно поэтому в [SYNC-SETUP.md](SYNC-SETUP.md) таблица закрыта наглухо: с одним ключом `anon`
нельзя ни прочитать список строк, ни добраться до твоей — для этого нужен точный
64-значный идентификатор, который выводится из кода.

Что теоретически может посторонний с этим ключом — насоздавать в таблице мусорных строк
со случайными идентификаторами. Твои данные это не затронет, но при желании базу можно
захламить. Для личного проекта риск незначительный, а если однажды понадобится — в функцию
`sync_push` добавляется ограничение по частоте запросов.

**Про перенос данных.** Новый адрес — это для браузера новый сайт, и `localStorage` там пустой.
Переносить вручную ничего не нужно: включи синхронизацию на `localhost:4173`, дождись, пока
данные уедут на сервер, и введи тот же код на новом адресе — всё скачается само. `localhost`
считается защищённым адресом, поэтому синхронизация там работает.

**Про пересборку.** Настройки из `.env.local` вшиваются в сборку в момент `npm run build`.
Если поменяешь их — пересобери и залей `dist` заново.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер разработки с горячей перезагрузкой |
| `npm run build` | Проверка типов + сборка в `dist/` |
| `npm run preview` | Локальный сервер для собранной версии |
| `npm run typecheck` | Только проверка типов |
| `npm run smoke` | Быстрая проверка: отрисовывает все экраны и панели и ищет в разметке нужные подписи |

`npm run smoke` стоит прогонять после любой правки в `src/` — он ловит ошибки в компонентах
и пропавшие данные за секунду, без запуска браузера.

## Где лежат данные

Основное хранилище — `localStorage` браузера, то есть само устройство. Приложение полностью
работает без интернета и без сервера.

Если включить синхронизацию, к этому добавляется **зашифрованная** копия на сервере. Ключ выводится
из кода синхронизации и на сервер не попадает, поэтому прочитать её можно только этим кодом.
Подробнее — [SYNC-SETUP.md](SYNC-SETUP.md).

Что важно помнить:

- Если синхронизация не включена, компьютер и телефон — **два независимых набора данных**.
  Перенести можно через «Ещё» → «Выгрузить в файл» / «Загрузить из файла».
- Если очистить данные сайта в браузере, локальные кешбэки удалятся. Делай резервную копию
  или включи синхронизацию.
- Код синхронизации восстановить невозможно — сохрани его в менеджере паролей.

## Как устроена модель данных

Всё лежит в одном объекте `AppData`. Две неочевидные детали нужны именно для синхронизации:

- у каждого кешбэка есть `updatedAt` — при конфликте двух устройств побеждает более поздняя правка;
- удаления записываются в `deleted` как «надгробия» с временем. Без них второе устройство,
  ещё не знающее об удалении, присылало бы удалённое обратно. Надгробия живут полгода
  и потом выбрасываются, чтобы список не рос без конца.

Схема версионируется: `normalizeData()` поднимает старые данные до текущего формата,
поэтому кешбэки, введённые до появления синхронизации, не теряются.

## Откуда список банков

Реестр участников СБП: `https://qr.nspk.ru/proxyapp/c2bmembers.json` — это источник данных
страницы [sbp.nspk.ru/participants](https://sbp.nspk.ru/participants?type=person).

Обновить список и логотипы можно, перекачав этот JSON и пересоздав `src/data/banks.json`
(поля `schema` → `id`, `bankName` → `name`) и картинки из `logoURL` в `public/logos/<id>.png`.

Проценты кешбэка заполняются вручную — банки не отдают их автоматически ни через какое API.
